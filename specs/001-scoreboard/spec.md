# Feature Specification: 신축매입약정 사업지 스코어보드

**Feature Branch**: `001-scoreboard`

**Created**: 2026-09-12

**Status**: Draft

**Input**: User description: "새사주 신축매입약정 사업지 스코어보드를 만든다. 단일 페이지 정적 사이트다. 기존 index.html, css/, js/, data/sites.json이 이미 있다. 이를 기준선으로 삼되 spec은 요구사항대로 작성한다."

**Baseline**: `index.html`, `css/`, `js/`, `data/sites.json`이 이미 저장소에 존재한다. 이 스펙은 그 기존 구현을 기준선(baseline)으로 삼아 기대 동작을 명문화한 것이며, 신규 프로젝트가 아니라 기존 산출물의 요구사항 정합성 검증 및 향후 변경의 기준으로 사용한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 히어로에서 종합 등급 요약 확인 (Priority: P1)

방문자는 첫 화면(히어로)에서 사이트 제목 "신축매입약정 사업지 스코어보드"와 4개 사업지의 종합 등급 요약을 본다.

**Why this priority**: 첫 화면은 방문자가 사이트의 목적과 4개 사업지의 전반적 평가 수준을 즉시 파악하게 하는 진입점이며, 이것이 없으면 나머지 스크롤 경험의 맥락이 성립하지 않는다.

**Independent Test**: 페이지를 열었을 때 스크롤 없이 제목과 4개 사업지 각각의 등급(A/B/C/D)이 보이는지 확인하는 것만으로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 방문자가 사이트에 처음 접속했을 때, **When** 페이지가 로드되면, **Then** 히어로 영역에 "신축매입약정 사업지 스코어보드" 제목과 4개 사업지 각각의 이름·종합 등급이 표시된다.
2. **Given** 히어로가 표시된 상태에서, **When** 방문자가 등급 표시를 확인하면, **Then** 등급은 문자(A/B/C/D)로 명시되어 색상 없이도 식별 가능하다.

---

### User Story 2 - 스크롤 기반 사업지 전환 탐색 (Priority: P1)

스크롤하면 사업지 4곳이 순서대로(창동 → 공릉동 → 창신동 → 부평) 하나의 연속된 화면 안에서 앞으로 들어오며 전환된다.

**Why this priority**: 스크롤 전환은 이 사이트의 핵심 탐색 방식이며, 각 사업지 상세 정보(User Story 3)에 도달하기 위한 유일한 경로다.

**Independent Test**: 페이지 최상단에서 끝까지 스크롤하며 4개 섹션이 창동→공릉동→창신동→부평 순서로, 하나의 화면 안에서 순차적으로 전환되는지 관찰하는 것으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 히어로 다음 위치에서, **When** 방문자가 아래로 스크롤하면, **Then** 창동 섹션이 가장 먼저 나타난다.
2. **Given** 한 사업지 섹션이 표시된 상태에서, **When** 계속 스크롤하면, **Then** 다음 사업지 섹션이 앞으로 들어오며 이전 섹션을 대체하고, 전체 진행 순서는 창동 → 공릉동 → 창신동 → 부평이다.

---

### User Story 3 - 사업지 상세 정보 및 평가 확인 (Priority: P1)

각 사업지 섹션은 (a) 항공사진/지도 이미지, (b) 소개 문단 2개, (c) 필지 정보 5항목(지번·대지면적·용도지역·예상 세대수·진행단계), (d) 5개 평가항목 점수 게이지와 종합 등급 배지를 보여준다. 섹션 진입 시 이미지가 확대→축소되고 텍스트가 순차 등장하며 점수 게이지가 0에서 실제 점수까지 차오른다.

**Why this priority**: 사업지별 상세 정보와 평가 근거를 제공하는 것이 이 스코어보드의 본질적 가치이며, 나머지 기능(히어로 요약, 비교표)은 이 상세 정보를 요약/재정렬한 파생물이다.

**Independent Test**: 사업지 섹션 하나에 진입해 이미지·소개 문단 2개·필지 정보 5항목·평가 게이지 5개·등급 배지가 모두 표시되고, 진입 애니메이션(이미지 스케일, 텍스트 등장, 게이지 채움)이 재생되는지 확인하는 것으로 독립 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 방문자가 한 사업지 섹션에 스크롤로 진입했을 때, **When** 섹션이 화면에 들어오면, **Then** 항공사진/지도 이미지, 소개 문단 2개, 필지 정보 5항목(지번·대지면적·용도지역·예상 세대수·진행단계), 5개 평가항목 게이지, 종합 등급 배지가 모두 표시된다.
2. **Given** 섹션 진입 애니메이션이 트리거된 시점, **When** 애니메이션이 재생되면, **Then** 이미지는 확대에서 축소로, 텍스트는 순차적으로, 점수 게이지는 0에서 각 항목의 실제 점수까지 차오르며 종료된다.
3. **Given** 어떤 사업지의 이미지 파일 로딩이 실패한 경우, **When** 섹션이 렌더링되면, **Then** 이미지 자리에 surface-1 색상의 빈 타일과 사업지명 텍스트가 대체 표시된다.

---

### User Story 4 - 비교 표에서 순위 확인 및 재정렬 (Priority: P2)

마지막 섹션은 4개 사업지를 합계 점수 내림차순으로 정렬한 비교 표다. 열 헤더를 클릭하면 해당 항목 기준으로 재정렬된다. 동점이면 입지 점수가 높은 쪽이 앞이다.

**Why this priority**: 개별 상세 섹션(P1)을 다 본 뒤 사업지 간 비교·우선순위 판단을 돕는 부가 기능으로, 상세 정보 없이도 상대적 가치를 더하지만 핵심 정보 전달(P1)이 선행되어야 의미가 있다.

**Independent Test**: 비교 표만 단독으로 로드해 기본 정렬(합계 점수 내림차순, 동점 시 입지 점수 우선)을 확인하고, 각 열 헤더를 클릭해 재정렬되는지 확인하는 것으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 방문자가 비교 표 섹션에 도달했을 때, **When** 표가 처음 렌더링되면, **Then** 4개 사업지가 합계 점수 내림차순으로 나열되고, 합계 점수가 동일한 경우 입지 점수가 높은 사업지가 먼저 나온다.
2. **Given** 비교 표가 표시된 상태에서, **When** 방문자가 특정 열 헤더(예: 사업성 점수)를 클릭하면, **Then** 표가 해당 항목 기준 내림차순(또는 재클릭 시 오름차순)으로 재정렬된다.

---

### User Story 5 - 상단 내비게이션으로 바로가기 (Priority: P3)

상단 고정 내비게이션에서 사업지 이름을 클릭하면 해당 섹션으로 부드럽게 스크롤한다.

**Why this priority**: 순차 스크롤 탐색(P1)의 보조 수단으로, 없어도 스크롤로 모든 콘텐츠에 도달 가능하지만 재방문·특정 사업지 재확인 시 편의를 높인다.

**Independent Test**: 페이지 아무 위치에서나 상단 내비게이션의 사업지 이름을 클릭해 해당 섹션으로 스크롤 이동하는지 확인하는 것으로 독립 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 방문자가 페이지의 임의 위치에 있을 때, **When** 상단 내비게이션에서 특정 사업지 이름을 클릭하면, **Then** 해당 사업지 섹션으로 화면이 부드럽게 스크롤 이동한다.

---

### User Story 6 - 모바일 환경에서의 축소된 경험 (Priority: P2)

모바일(375px)에서는 이미지와 글이 세로로 쌓이고, 스크롤 연출은 단순 페이드로 축소된다.

**Why this priority**: 모바일 방문자도 핵심 정보(P1)에 접근할 수 있어야 하며, 데스크톱 전용의 정교한 스크롤 연출이 좁은 화면에서 오히려 가독성을 해치므로 별도 축소 경험이 필요하다.

**Independent Test**: 뷰포트를 375px로 설정해 각 사업지 섹션의 이미지·텍스트가 세로로 쌓여 표시되고, 진입 시 페이드 전환만 재생되는지 확인하는 것으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 뷰포트 폭이 375px인 모바일 환경에서, **When** 사업지 섹션이 렌더링되면, **Then** 이미지와 텍스트 블록이 가로 배치가 아닌 세로로 순서대로 쌓인다.
2. **Given** 모바일 환경에서 섹션에 스크롤로 진입할 때, **When** 진입 애니메이션이 트리거되면, **Then** 이미지 확대/축소나 게이지 스크럽 연출 대신 단순 페이드 인만 재생된다.

---

### Edge Cases

- 이미지 파일 경로가 존재하지 않거나 로딩에 실패하면 어떻게 되는가? → surface-1 색 빈 타일 + 사업지명 텍스트로 대체 표시된다(User Story 3 참조).
- `data/sites.json`에 저장된 `total`/`grade` 값이 `scores` 합계로 재계산한 값과 다르면 어떻게 되는가? → 화면에는 재계산된 값이 표시되고, 콘솔에 불일치 경고가 기록된다.
- 비교 표에서 합계 점수가 동점인 사업지가 2곳 이상이면 어떻게 정렬되는가? → 입지 점수가 더 높은 사업지가 앞선다.
- 사용자가 OS/브라우저에서 `prefers-reduced-motion: reduce`를 설정한 경우 어떻게 되는가? → 스크롤 전환, 이미지 확대/축소, 게이지 채움 애니메이션이 모두 비활성화되고 각 요소는 최종 상태로 즉시 렌더링된다.
- 사업지가 정확히 4곳이 아니게 되면(추가/삭제) 어떻게 되는가? → 스코어보드는 `data/sites.json`에 등록된 개수만큼 섹션과 비교 표 행을 렌더링하며, 4곳이라는 숫자에 하드코딩된 로직이 없어야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 히어로 영역에 사이트 제목 "신축매입약정 사업지 스코어보드"와 각 사업지의 이름·종합 등급을 표시해야 한다.
- **FR-002**: 시스템은 4개 사업지 섹션을 창동 → 공릉동 → 창신동 → 부평 순서로, 스크롤에 따라 연속적으로 전환되는 하나의 화면 안에서 제공해야 한다.
- **FR-003**: 각 사업지 섹션은 항공사진/지도 이미지 1개, 소개 문단 2개, 필지 정보 5항목(지번, 대지면적, 용도지역, 예상 세대수, 진행단계), 5개 평가항목(입지, 토지 조건, 사업성, 심의 통과 가능성, 사회적 가치) 점수 게이지, 종합 등급 배지를 표시해야 한다.
- **FR-004**: 시스템은 사업지 섹션에 진입할 때 이미지 확대→축소 전환, 텍스트 순차 등장, 점수 게이지가 0에서 실제 점수까지 채워지는 애니메이션을 재생해야 한다.
- **FR-005**: 시스템은 마지막 섹션에 4개 사업지를 합계 점수 내림차순으로 정렬한 비교 표를 표시해야 하며, 합계 점수가 동일한 경우 입지 점수가 높은 사업지를 먼저 표시해야 한다.
- **FR-006**: 사용자는 비교 표의 열 헤더를 클릭하여 해당 항목 기준으로 표를 재정렬할 수 있어야 한다.
- **FR-007**: 사용자는 상단 고정 내비게이션에서 사업지 이름을 클릭하여 해당 섹션으로 부드럽게 스크롤 이동할 수 있어야 한다.
- **FR-008**: 시스템은 뷰포트 폭 375px 기준 모바일 환경에서 이미지와 텍스트를 세로로 쌓아 배치하고, 진입 애니메이션을 단순 페이드로 축소해야 한다.
- **FR-009**: 시스템은 각 사업지의 `total`(합계 점수)과 `grade`(등급)를 `data/sites.json`에 저장된 값이 아니라 `scores`의 5개 항목 합계로부터 클라이언트에서 재계산하여 표시해야 하며, 등급 구간은 A(85점 이상), B(70~84점), C(55~69점), D(55점 미만)를 따라야 한다.
- **FR-010**: 재계산된 `total`/`grade`가 `data/sites.json`에 저장된 값과 다를 경우, 시스템은 해당 사업지명과 두 값을 개발자 콘솔에 경고로 기록해야 한다(화면 표시는 재계산 값을 사용).
- **FR-011**: 이미지 로딩에 실패하면 시스템은 해당 이미지 자리에 surface-1 색상의 빈 타일과 사업지명을 표시해야 한다.
- **FR-012**: 등급(A/B/C/D)은 항상 문자 텍스트로 표시되어야 하며, 색상이 아닌 표면 밝기(surface lift)와 pill 형태 배지로 시각적으로 구분되어야 한다.
- **FR-013**: 모든 이미지 요소는 대체 텍스트(alt)를 가져야 한다.
- **FR-014**: 사용자가 `prefers-reduced-motion: reduce`를 설정한 경우, 시스템은 스크롤 전환, 이미지 확대/축소, 게이지 채움 등 모든 애니메이션을 비활성화하고 각 요소를 최종 상태로 즉시 표시해야 한다.
- **FR-015**: 모든 사업지 콘텐츠(이름, 지번, 면적, 용도지역, 세대수, 진행단계, 이미지 경로, 소개 문단, 항목별 점수)는 `data/sites.json` 한 곳에서만 읽어와야 하며, 사업지 데이터 추가/수정/삭제는 이 파일 편집만으로 반영되어야 한다.

### Key Entities

- **사업지(Site)**: 스코어보드가 평가하는 개별 신축매입약정 대상 부지. 식별자, 이름, 자치구, 대지면적, 용도지역, 예상 세대수, 진행단계, 대표 이미지 경로, 소개 문단 2개, 5개 평가항목별 점수, (참고용으로 저장된) 합계 점수와 등급을 속성으로 가진다.
- **평가항목(Score Category)**: 입지, 토지 조건, 사업성, 심의 통과 가능성, 사회적 가치의 5개 고정 항목. 각 항목은 라벨과 만점(max)을 가지며 사업지별 점수의 상한을 정의한다.
- **등급 구간(Grade Rule)**: 합계 점수 구간을 A/B/C/D 등급으로 매핑하는 규칙(A ≥ 85, B 70~84, C 55~69, D < 55).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 방문자는 페이지 로드 후 스크롤 없이 3초 이내에 사이트 제목과 4개 사업지의 등급을 파악할 수 있다.
- **SC-002**: 방문자는 스크롤만으로 4개 사업지의 상세 정보(이미지, 소개, 필지 정보, 평가 점수)에 순서대로 도달할 수 있으며, 도달률(각 섹션이 화면에 표시되는 비율)은 스크롤을 끝까지 내린 방문자 기준 100%다.
- **SC-003**: 방문자는 비교 표에서 열 헤더 클릭 한 번만으로 원하는 평가항목 기준 순위를 확인할 수 있다.
- **SC-004**: 표준 데스크톱 및 375px 모바일 뷰포트 모두에서 모든 텍스트와 등급 표시가 색상 구분 없이도(문자만으로) 식별 가능하다.
- **SC-005**: 자동화된 페이지 성능 측정(Lighthouse Performance)에서 90점 이상을 기록한다.
- **SC-006**: `prefers-reduced-motion`을 설정한 방문자는 애니메이션 없이도 모든 콘텐츠(이미지, 텍스트, 점수, 등급)에 동일하게 접근할 수 있다.
- **SC-007**: 사업지 데이터를 추가·수정하는 작업자는 `data/sites.json` 파일 편집만으로 화면 반영을 완료할 수 있으며, 코드 수정이 필요하지 않다.

## Assumptions

- 기존에 존재하는 `index.html`, `css/`, `js/`, `data/sites.json`을 이 스펙의 기준선(baseline)으로 삼는다. 이 스펙은 새 기능을 처음부터 설계하는 것이 아니라, 기존 산출물이 만족해야 할 기대 동작을 명문화한 것이다.
- 대상 사업지는 창동, 공릉동, 창신동, 부평 4곳으로 고정된 것이 아니라 `data/sites.json`에 등록된 목록을 따르며, 현재는 이 4곳이 등록되어 있다고 가정한다.
- 디자인 시스템(색상, 타이포그래피, 컴포넌트 토큰)은 루트의 `DESIGN.md`를 단일 출처로 삼으며, 이 문서에서 별도 재정의하지 않는다(디자인 세부 규칙은 프로젝트 constitution 및 DESIGN.md에 위임).
- 이미지 형식/용량(WebP, 1600px 이하)과 Lighthouse 성능 90점 이상은 비기능 목표로서 SC-005에 반영했고, 구체적 구현 방식은 계획(plan) 단계에서 다룬다.
- 사용자 인증, 다국어 지원, 서버 사이드 데이터 저장은 이 스코어보드의 범위 밖이며 다루지 않는다.
