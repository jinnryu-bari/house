# Quickstart: 신축매입약정 사업지 스코어보드 검증

이 기능은 빌드 스텝이 없는 정적 사이트다. 아래 절차로 로컬에서 실행하고 spec.md의 사용자 스토리를 검증한다.

## Prerequisites

- 아무 정적 파일 서버(브라우저의 `fetch("data/sites.json")`가 `file://`에서는 CORS로 막히므로 반드시 HTTP로 서빙해야 함)
- 최신 Chrome/Edge/Firefox 중 하나

## Run

저장소 루트에서:

```bash
python -m http.server 8000
# 또는: npx http-server -p 8000   (npm 설치는 개발 편의용일 뿐, 배포 산출물에는 영향 없음)
```

브라우저에서 `http://localhost:8000/` 접속.

## Validation Scenarios (spec.md 대응)

각 항목은 spec.md의 User Story/Acceptance Scenario를 그대로 수동 검증하는 절차다.

1. **히어로 요약 (US1)**: 페이지 최초 로드 시 스크롤 없이 "신축매입약정 사업지 스코어보드" 제목과 4개 사업지명+등급(A/B/C/D 문자)이 보이는지 확인.
2. **씬 순서/전환 (US2)**: 데스크톱 폭(≥768px)에서 위→아래로 천천히 스크롤하며 창동 → 공릉동 → 창신동 → 부평 순서로, 각 섹션이 pin된 상태에서 이미지가 확대(1.15)에서 축소(1.0)로 줄어들고 다음 섹션이 아래에서 위로(`translateY(100%)→0`) 들어오는지 확인.
3. **사업지 상세 (US3)**: 한 섹션에 진입할 때 이미지, 소개 문단 2개, 필지 정보 5항목(지번/대지면적/용도지역/예상 세대수/진행단계), 5개 게이지, 등급 배지가 모두 나타나고 게이지가 0에서 실제 점수까지 채워지는지 확인. `data/sites.json`의 `image` 경로를 일부러 잘못된 값으로 바꿔 새로고침 → 해당 섹션에 surface-1 배경 + 대체 텍스트가 나오는지 확인 후 원복.
4. **불일치 로깅 (FR-010)**: 브라우저 DevTools 콘솔을 연 상태로 `data/sites.json`의 한 사업지 `total` 값을 `scores` 합계와 다르게 임시로 바꿔 새로고침 → 콘솔에 사업지명+두 값이 포함된 경고가 뜨는지, 화면에는 재계산된 값이 표시되는지 확인 후 원복.
5. **비교 표 정렬 (US4)**: 페이지 끝까지 스크롤해 비교 표가 합계 점수 내림차순으로 정렬돼 있는지 확인. 임의의 열 헤더(예: "사업성")를 클릭해 해당 항목 기준으로 재정렬되는지, 같은 헤더를 다시 클릭하면 오름차순↔내림차순이 토글되는지 확인. 페이지를 새로고침해 기본 정렬(합계 내림차순)로 되돌아가는지(=정렬 상태가 저장되지 않음, Constitution VII) 확인.
6. **상단 내비게이션 (US5)**: 페이지 하단부에서 상단 고정 내비게이션의 임의 사업지명을 클릭 → 해당 섹션으로 부드럽게 스크롤 이동하는지 확인.
7. **모바일 축소 경험 (US6)**: 브라우저 DevTools의 기기 툴바에서 폭 375px로 설정 → 각 섹션의 이미지/텍스트가 세로로 쌓이는지, 섹션 진입 시 pin/scrub 대신 단순 페이드만 재생되는지 확인.
8. **모션 감소 (FR-014)**: OS 설정에서 "동작 줄이기"(macOS) / "애니메이션 표시 안 함"(Windows) 활성화(또는 DevTools Rendering 탭의 `prefers-reduced-motion: reduce` 에뮬레이션) → 페이지를 새로고침해 스크롤 pin/scrub, 이미지 확대/축소, 게이지 채움 애니메이션 없이 모든 콘텐츠가 즉시 최종 상태로 보이는지 확인.
9. **성능 (SC-005)**: Chrome DevTools Lighthouse 탭에서 Performance 카테고리만 선택해 감사 실행 → 점수 90 이상 확인.
10. **데이터 단일 소스 (SC-007)**: `data/sites.json`에 다섯 번째 사업지를 임시로 추가(다른 파일 수정 없이) → 새로고침 시 히어로 요약, 씬, 비교 표에 다섯 번째 사업지가 자동으로 나타나는지 확인 후 원복.

## Known Gaps at This Point (plan.md 참조)

아래 항목은 위 시나리오 중 일부가 **현재 실패할 수 있음**을 의미하며, `/speckit-tasks`에서 작업으로 전환해 해결한다:

- 시나리오 5의 "동점 시 입지 점수 우선" 세부 규칙은 현재 구현에 없다(총점이 우연히 동점인 사업지가 생기기 전까지는 눈에 띄지 않을 수 있음).
- `gradient-spotlight-card`/`product-mockup-tile` 클래스명 사용 여부는 시각적으로는 드러나지 않고 코드 검사(devtools Elements 패널에서 A등급 카드/이미지 타일의 class 속성 확인)로만 확인 가능하다.
